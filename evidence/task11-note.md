## Generator design
- **Parser:** `typescript` 6.0.3, already installed and pinned. `ts.transpileModule(…, { reportDiagnostics: true })` reports syntax errors, and `ts.createSourceFile(…, ScriptKind.TS)` builds the syntax tree. Specs are read as text and never imported, required or run.
- **Loading:** `typescript` is imported lazily, only by `--write`, `--check` and the `--from-hook` refresh. The session and logging paths never load it.
- **Supported syntax** (what the 4 specs use):
  - top-level imports;
  - `test.describe(<literal>, () => {…})`;
  - inside it: `runIfEnv(…)`, variable declarations, `test.beforeEach/afterEach/beforeAll/afterAll(…)`, and `test(<literal>, async (…) => {…})`.
- **Refused, with file:line:**
  - dynamic titles (template with `${}`, variable, concatenation);
  - `test.describe.only/skip/serial/…`, a nested `describe`, `test.only/skip/fixme/…`;
  - tests made in loops, `forEach` or a top-level `test`;
  - `test` redefined (`base.extend`), or `test` not imported from `@playwright/test`;
  - no tests; a title containing `<!--`/`-->`; parse errors.

  No note is created for a refused spec.
- **Mapping:** `tests/<path>.spec.ts` → `vault/tests/<path>.md`.
- **Block between `<!-- generated:start -->` and `<!-- generated:end -->`:**
  - the source link;
  - the SHA-256 of the source bytes;
  - the parser and its status;
  - the literal titles (describe › test);
  - the Page Object imports (an import that resolves under `pages/`).

  There are no timestamps, so unchanged input gives byte-identical output.
- **Text outside the markers** is spliced as raw bytes, so it is kept byte for byte. Anything other than exactly one start followed by one end is refused, and nothing is written.
- **Deleted source with a note:** `source deleted: … Review <note>, then remove it or archive it outside vault/tests; its text is never erased automatically`, exit 1. With no note left, this is a valid deletion (exit 0). The full run also reports source-less notes and unmarked files under `vault/tests/`.
- **Arguments:** rejected with exit 2:
  - unknown or conflicting flags, `--files` twice or empty, paths without `--files`;
  - paths outside the project, outside `tests/`, not `*.spec.ts`, or symbolic links.

  A deleted path is accepted.
- **Loop protections are kept:**
  - (a) `--from-hook` still ignores paths inside `vault/`, so a note edit never triggers generation;
  - (b) `sessions.log` still counts before it appends;
  - the generator writes with `fs`, not Claude's tools, so it never re-enters PostToolUse.

The stage 1 generator is unchanged apart from the `--stage` flow. The `--write`/`--check` summary line is unchanged when `--stage` is not used.

**`--links`** checks every `.md` under `vault/`:
- **Link forms:** `[label](target)` (including `<angle>` targets and titles), `[id]: target` and `[[wikilinks]]` (from the vault root, with `|label` and `#heading`). `.md` is optional, `#fragment` and `?query` are stripped, and a folder counts as a target.
- **Ignored:** images, `![[embeds]]`, web, mail and other scheme links, inline code, and fenced code (``` and ~~~).
- **Errors (exit 1):** a missing target, a root-relative link, a link outside the project.
- **Warnings only:** a maintained note that no other note links to. Exempt: `_map.md`, `_raw/`, `_changelog/`, `sources/`, `12-progress-report/`.
- Heading fragments and external sites are not checked.

**Staging safety (`stagingProblems`, also run again inside `--stage`)**, for each selected spec:
- the spec has unstaged changes, meaning it is partially staged;
- its note exists but is untracked, so it needs review;
- its tracked note has unstaged edits;
- the spec is gone but its note remains, so it needs reviewed cleanup.

`--stage` writes nothing if any check or any plan fails. After writing, it checks again that each spec is still fully staged and each note holds exactly what was written. Then it runs `git --literal-pathspecs add -- <notes>` for the written notes only. Selected specs come from `git diff --cached --name-status -z -M`, parsed NUL-delimited; renames contribute both paths.

**Root pinning:** `spec-notes.mjs` and the pre-push vault step take the root from `git rev-parse --show-toplevel`, never from an inherited `CLAUDE_PROJECT_DIR`. The tests run with a decoy `CLAUDE_PROJECT_DIR` and prove the decoy is untouched.

# Additional rule: guide H1 (warning only)

## Rule
- **Purpose:** a human guide is read for navigation, and its H1 is the title readers, the map and note apps show. Front matter (`id:`, `type:`) does not replace it.
- **Scope:** `.md` files under `vault/03-framework/`, matched by the coded pattern `GUIDE_SCOPE = /^vault\/03-framework\/.+\.md$/` in `scripts/vault-sync.mjs`. Outside it: imports (`sources/`), logs (`_changelog/`), journals (`12-progress-report/`), generated test notes (`tests/`), `_map.md`, `_context.md`, `_raw/`, and anything outside `vault/`.
- **What counts as an H1:** an ATX heading (`# Title`, at most 3 leading spaces) or a setext heading (text followed by `===`), outside code.
- **What does not count:** the leading YAML front matter (between the first two `---` lines, so `# yaml comment` there is not a heading), fenced code (``` and ~~~), lines indented 4 or more spaces (indented code), inline code, and `##` or deeper headings.
- **Severity: warning.** The rule prints `vault-links: WARN guide without H1 <file>: add a "# Title" line outside code blocks` on stdout and counts it in the summary's `warning(s)`. It **never changes the exit code**: only broken links exit 1, so `vault:validate` and pre-push still pass on a heading warning alone.
- **Where:** part of `--links` (`hasH1()` plus a few lines in `runLinks()`). No new mode or flag, and no change to `--check`, the generator or the Git hooks.
